details come from `report/evidence/maps/maps_info.json`.

**How the representative trip was chosen:** the student-test trip closest to the
partition medians of both trip length (median 1,420 points) and final Top-1
(median 0.913). That is trip 00000007, with 1,354 points and Top-1 0.900. It also happens to
be the one trip where the HMM lowers accuracy, so it shows both behaviours.

The reference route appears on these maps because they are offline report
figures for student-test trips. The live UI never receives reference routes.

## 2. Pipeline

**Candidate generation** (`src/map_matching/candidates.py`)
* Each trip is projected to its UTM zone (metres).
* Road arcs are densified every 10 m into a KD-tree. For each GPS point, every arc within
  50 m is found by exact point-to-segment distance, and the closest 8 are kept.
* If none is found, the radius widens to 150 m. If still none, the point is left unmatched.
* Student-test candidate miss rate: 0.42 %. Training: 9.21 %, mostly the two misaligned trips.

**Classifier** (`src/models/inference.py`): the tuned HistGradientBoosting scores every
(point, candidate) pair with 19 features.

**HMM** (`src/map_matching/hmm.py`)
* **Hidden states:** the candidate arcs of each point, with the point's position along each arc.
* **Emission:** 0.5 × log(classifier probability) + 0.5 × (−½ (distance / 12 m)²),
  floored at −50. The classifier's output is used **only** here.
* **Transition:** the driving distance between the two projected positions (bounded
  Dijkstra on the directed road graph) compared with the straight-line distance
  between the two GPS points: −|driving − straight| / (40 m × √Δt).
  * Unreachable within 4 × straight distance + 200 m means impossible.
  * Going backwards along a one-way arc by more than 5 m is not allowed.

**Viterbi** (`src/map_matching/viterbi.py`)
* Log-space recurrence: best[t][j] = emission[t][j] + max over i of
  (best[t−1][i] + transition[i→j]), with back-pointers.
* If a point has no candidates, or no transition into it is possible, the current
  segment is closed and decoding restarts. These restarts are reported as "segment breaks".

**Route output** (`src/map_matching/reconstruction.py`)
* One arc per GPS point, repeated arcs collapsed.
* Gaps between consecutive arcs are bridged by the shortest road path only when it is short.
* Returns route arc ids, polylines, continuity, breaks and timings.

## 3. API (`src/api/`, FastAPI)

| Endpoint | Evidence |
|---|---|
| `GET /health` | `evidence/api/01_health.txt` (200, model loaded) |
| `GET /trips` | `evidence/api/02_trips.txt` (10 student-test trips) |
| `POST /reconstruct` | `evidence/api/03_reconstruct_00000052_full.json` and `_shortened.txt` (200 in 75 ms; Top-1 1.000 with HMM, 0.969 classifier only) |
| `GET /trips/{id}/network` | used by the UI; tested in `tests/test_models_api.py` |
| Errors | `evidence/api/04_error_responses.txt` (404 for an unknown trip, 422 for an invalid mode) |
| Server log | `evidence/api/server_terminal_output.txt`: the server's own log lines for each request above |
| Swagger docs | `evidence/api/swagger_docs.png` |

There is **no separate `/predict` endpoint**: per-point predictions (arc id,
matched position, classifier probability) come back inside `/reconstruct`.

These captures came from an API instance serving the **student-test** trips on port 8001.
Evaluator trips were not reconstructed.

## 4. UI (`frontend/`)

Static HTML and JavaScript with Leaflet. It connects to an API URL and lists its trips.
Selecting a trip draws nearby roads; "Match route" calls `/reconstruct` and draws the
GPS points and matched route. It shows Top-1, a one-line summary, the details table,
and a side-by-side table of classifier vs HMM.

| Screenshot | Shows |
|---|---|
| `evidence/ui/01_connected_trip_list.png` | Connected to the API, 10 trips listed |
| `evidence/ui/02_route_reconstructed_trip_00000007.png` | Reconstructed route, results and side-by-side table for the representative trip |
| `evidence/ui/03_route_reconstructed_trip_00000009.png` | Another trip (Top-1 0.907) |
| `evidence/ui/04_error_api_unreachable.png` | Error state when the API cannot be reached |
| `evidence/ui/05_mobile_layout.png` | Narrow-screen layout |

The UI has no file-upload input. The guidelines' workflow is "pick one of the
reserved trips", which is what the UI does.
